# 01 · 文献调研与选题

> 科研的第一步不是"想一个 idea"，而是"搞清楚别人已经做到哪、哪里还没做好"。调研做扎实了，选题、写引言、写相关工作全都水到渠成。

## 一、调研要回答的三个问题

1. **这个方向的现状是什么？** —— 主流做法、公认 baseline、公认数据集与指标。
2. **公认的难点 / 未解决的问题（gap）在哪？** —— 别人反复提到"未来工作"的地方，往往就是 gap。
3. **我能切入的角度是什么？** —— 你的资源、技能、数据能撬动哪个 gap。

调研的终点是一句能写在纸上的话：
> **"针对 [任务]，现有方法在 [某情况] 下会 [某问题]；本文提出 [某做法] 来解决它。"**

## 二、去哪里找文献

| 渠道 | 用途 | 链接 |
|---|---|---|
| **Google Scholar** | 按关键词/标题搜，看被引数判断影响力 | https://scholar.google.com |
| **Semantic Scholar** | 看"施引文献 / 参考文献"顺藤摸瓜，找综述 | https://www.semanticscholar.org |
| **arXiv** | 追最新预印本（AI/信号领域几乎都先上 arXiv） | https://arxiv.org |
| **Papers With Code** | 按任务看 SOTA 排行榜，每条带开源代码 | https://paperswithcode.com |
| **DBLP** | 查某会议/期刊/作者的完整论文列表 | https://dblp.org |
| **Connected Papers** | 输入一篇论文，可视化其"学术邻居" | https://www.connectedpapers.com |
| **IEEE Xplore / ACM DL** | 查会议/期刊正式版与官方元数据 | https://ieeexplore.ieee.org |

**检索技巧**：
- 先找 **1–2 篇近两年的综述（survey / review）**，它会帮你把整个领域的脉络梳理清楚，参考文献就是你的第一批"必读清单"。
- 用**任务名 + 方法关键词**组合搜索，例如 `speech enhancement transformer real-time`。
- 找到一篇好文后，往两个方向扩展：它引了谁（往前追溯源头）、谁引了它（往后看最新进展）。
- 关注该方向 **1–3 个核心课题组**，跟他们的主页/Google Scholar，能第一时间看到新工作。

## 三、如何读一篇论文：三遍法

出自 S. Keshav《How to Read a Paper》，科研人必备的高效读论文法。

**第一遍（5–10 分钟，判断"要不要细读"）**
- 只读：标题、摘要、引言、各节标题、结论、图表。
- 读完能回答：这篇解决什么问题？属于哪类方法？主要贡献是什么？
- 大多数论文到这一遍就够了——快速筛掉不相关的。

**第二遍（约 1 小时，抓住"做了什么"）**
- 读正文，但**可以跳过证明和繁琐推导**。
- 重点看图表：它们往往浓缩了核心结果。
- 在旁边记下：关键假设、方法主干、和你的问题的关系。
- 标出你没看懂或觉得存疑的地方。

**第三遍（数小时，做到"能复现/能挑战"）**
- 只对少数最关键的论文做。假装自己要重新实现它。
- 检查每一个假设、每一步推导，思考"如果是我会怎么做、哪里能改进"。
- 读完你应该能凭记忆复述其结构，并说出它的优点与局限——这正是你写"相关工作"和找 gap 的素材。

> 💡 用 [文献综述对比矩阵](../templates/literature-review-matrix.md) 把读过的论文横向排开对比，gap 会自己浮现出来。

## 四、文献管理：别让引用变成灾难

投稿时最崩溃的场景之一，就是几十篇参考文献格式错乱、citation key 冲突。**从第一天就用工具管理。**

- **[Zotero](https://github.com/zotero/zotero)**（推荐）：一键抓取网页/PDF 元数据，配 **[Better BibTeX](https://github.com/retorquere/zotero-better-bibtex)** 生成稳定的 citation key（如 `vaswani2017attention`），直接导出 BibTeX 给 LaTeX 用。
- **[JabRef](https://github.com/JabRef/jabref)**：纯 BibTeX 工作流，条目干净可控。
- 建立**分主题的文件夹/标签**，读完随手记一句"这篇的核心贡献 + 与我的关系"。

更多工具见 [08 · GitHub 科研工具箱](./08-tools.md)。

## 五、从调研到选题：什么是"好问题"

一个值得做的研究问题，通常同时满足：

| 标准 | 自问 |
|---|---|
| **重要（Important）** | 解决它，别人会在意吗？有实际或理论意义吗？ |
| **新颖（Novel）** | 别人还没做过，或没这样做过？ |
| **可行（Feasible）** | 用我现有的数据/算力/时间，能验证吗？ |
| **可检验（Falsifiable）** | 我能设计实验来证明它对或错吗？ |
| **范围合适（Scoped）** | 一篇论文/一次课题能讲完，而不是一个大话题？ |

**新手常见误区**：
- ❌ 问题太大：「用 AI 解决语音问题」——这是方向不是问题。
- ❌ 增量太小：只是把 A 方法换个数据集跑一遍。
- ❌ 无法验证：提出一个漂亮想法，但没有数据/指标能证明。
- ✅ 好的样子：「现有实时语音增强模型在极低信噪比下会引入音乐噪声；本文用子带建模 + XX 机制缓解它，并在 DNS Challenge 上验证。」

## 六、把调研沉淀成写作素材

调研阶段的笔记，直接就是论文两个部分的原料：

- **引言的"背景 + gap"** ← 你对现状和难点的总结。
- **相关工作** ← 你的文献对比矩阵，按"研究路线"分组，每组点出与你的不同。

所以调研时就带着"我以后要怎么写它"的意识做笔记，能省掉大量返工。写法见 [03 · 会议论文写作](./03-conference-paper.md) 的引言 / 相关工作两节。

## 本章 Checklist

- [ ] 读了至少 1 篇近两年综述，建立了领域脉络。
- [ ] 精读了 3–5 篇最相关论文（第三遍级别）。
- [ ] 用工具（Zotero 等）建立了文献库，能导出 BibTeX。
- [ ] 填好了文献对比矩阵，能说清主流方法与它们的局限。
- [ ] 能用一句话写出你的研究问题和假设。
- [ ] 确认了公认的数据集、baseline、评价指标。
