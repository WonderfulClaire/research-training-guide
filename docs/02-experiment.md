# 02 · 实验设计与执行

> 实验的唯一目的：**用证据支撑（或推翻）你的假设**。一篇论文能不能被接受，很大程度取决于实验能不能让审稿人信服"你的贡献是真的"。

## 一、先想清楚：实验要证明什么

动手跑之前，先把这句话写出来：
> **"如果 [我的方法] 真的有用，那么在 [数据集] 上用 [指标] 衡量，它应该比 [baseline] 好，并且 [某个消融] 会证明是 [某个模块] 起了作用。"**

这句话直接决定了你要做哪些实验。实验不是"把能跑的都跑一遍"，而是**每个实验对应一个要回答的问题**。

## 二、实验设计的四根支柱

### 1. Baseline（对照）
- 至少包含：**近 3 年的 SOTA** + **1–2 个经典/公认方法**。
- **公平设置**：相同数据划分、相同训练预算、相同评测协议。用别人不同设置下的数字直接比，会被审稿人一票否决。
- 能复现的 baseline 尽量自己复现；引用别人论文里的数字时，务必注明来源与设置。

### 2. 数据集
- 优先用**领域公认的公开数据集**（利于对比、利于复现）。
- 明确记录：规模、train/val/test 划分、预处理方式、采样率/分辨率等。
- **训练集、验证集、测试集严格隔离**。调参只能看验证集，测试集只在最后跑一次——否则就是信息泄漏。

### 3. 评价指标
- 用**领域公认指标**，并在论文里给出定义或引用。
  - 语音增强：PESQ、STOI、SI-SNR、DNSMOS…
  - 语音分离：SI-SNR/SI-SNRi、SDR…
  - 识别：WER/CER；分类：Accuracy、F1；检索：mAP…
- 单一指标常有偏，尽量**多指标交叉验证**。
- 除了效果，别忘了**效率指标**：参数量、FLOPs、推理时延、实时率（RTF）——很多会议（尤其 ICASSP）很吃"轻量/实时"。

### 4. 变量控制与消融（Ablation）
- **一次只改一个变量**，否则无法归因。
- **消融实验**是证明"每个模块都有用"的关键：逐个去掉/替换你的创新点，看性能掉多少。
- 消融不充分，是审稿人最爱挑的刺之一。你说某模块重要，就得有数据证明去掉它会变差。

## 三、可复现性（Reproducibility）：从第一天就做对

可复现不是发论文后才补的事，而是贯穿始终的工程习惯。它既让你的结果可信，也让你自己在几周后还能重跑。

**必做清单：**

- [ ] **固定随机种子**（Python / NumPy / 框架 / CUDA 都要设），并跑**多个种子取均值±方差**，别只报一次的运气结果。
- [ ] **锁定环境**：记录依赖版本（`requirements.txt` / `environment.yml` / Docker），注明硬件（GPU 型号）。
- [ ] **版本管理代码**：用 Git，每次出实验结果时打 tag 或记 commit hash，做到"结果 ↔ 代码"可追溯。
- [ ] **配置与代码分离**：超参用配置文件（YAML/JSON）管理，别硬编码，方便复现和扫参。
- [ ] **保存 checkpoint 与日志**，关键实验的产物要能找回。
- [ ] 论文里提供**足够的实现细节**（或开源代码链接），让别人能重跑。

> 报告结果时写成 `SI-SNR = 13.2 ± 0.3 dB (3 seeds)` 这样的形式，比一个孤零零的数字可信得多。

## 四、实验的工程化：让自己跑得快、错得少

- **实验追踪工具**：用 [Weights & Biases](https://wandb.ai)、[MLflow](https://mlflow.org) 或 TensorBoard 记录每次实验的超参、曲线、指标，避免"跑了一堆忘了哪个是哪个"。
- **实验命名规范**：给每次 run 起有意义的名字（如 `subband_seed1_lr1e-3`），配合 [实验记录日志模板](../templates/experiment-log.md) 手动记要点。
- **先小后大**：先用小数据/小模型/少 epoch 跑通全流程（overfit 一个 batch 验证代码正确），再上全量。
- **失败也要记**：什么设置没用、为什么，这些负结果能帮你避免重复踩坑，有时还能写进论文的分析部分。

## 五、结果分析：从数字到结论

跑完实验不等于做完实验。**分析**才体现研究深度：

- **主结果表**：与 baseline 定量对比，加粗最优值，常配参数量/复杂度列。
- **消融表**：证明每个组件的贡献。
- **深入分析**：收敛曲线、失败案例、可视化（如注意力图、频谱图对比）、在不同条件（信噪比/长度/噪声类型）下的表现。
- **诚实面对**：如果某指标上你不占优，如实报告并解释。审稿人对"报喜不报忧"极其敏感。

> 好的实验分析回答的是 **"为什么有用 / 什么时候失效"**，而不只是 **"有用"**。

## 六、常见实验陷阱（审稿人一眼看穿）

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 只报有利指标 | 被质疑 cherry-picking | 全面报告，含不利指标 |
| 和别人不同设置比 | 结果无效 | 统一数据/协议重新对比 |
| 不做消融 | 无法证明贡献归因 | 逐模块消融 |
| 单次运行、不报方差 | 结果不可信 | 多种子取均值±方差 |
| 测试集参与调参 | 信息泄漏、结果虚高 | 严格隔离 test set |
| 没有效率分析 | 轻量/实时类贡献站不住 | 报参数量/时延/RTF |

## 本章 Checklist

- [ ] 每个实验都对应一个明确要回答的问题。
- [ ] Baseline 选得公平、覆盖 SOTA 与经典。
- [ ] 数据划分严格隔离，指标是领域公认的。
- [ ] 关键创新点都有对应的消融实验。
- [ ] 固定种子、多次运行、报告均值±方差。
- [ ] 环境、代码版本、超参配置可追溯、可复现。
- [ ] 结果做了深入分析，不只是"我们更好"。
